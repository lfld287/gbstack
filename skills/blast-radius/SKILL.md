# 验证变更影响面

用 `grep` 找到的直接调用方只作入口。把主要精力放在搜索不到的契约与行为上。

1. 读 diff、相关 PR 和 commits，识别新增、删改的符号与未明说的行为变化。Git 命令一律带 `GIT_OPTIONAL_LOCKS=0`，产出 diff 的命令加 `--no-ext-diff --no-textconv`。
2. 提炼「变更之所以安全的唯一核心事实」。写成可证伪的断言，指出什么观察结果会推翻它。
3. 排查搜索盲区。核对第三方库的锁定版本、对应源码与本地 patch。追踪异步、microtask 和 teardown 的先后顺序，API JSON、DB 列和 wire 序列化的兼容性，跨语言消费、feature flag 组合与下游多跳调用。
4. 在授权范围内写最小脚本或测试，调用真实代码验证核心事实，记录命令、退出码和关键输出。单机直接验证。Swarm 由 Coordinator 派 `scout` 定位盲区，写脚本和实跑交给获授权的 `worker`。重大或影响广的变更用 `interrogate`，或由 Coordinator 派多视角只读评审并合并结果。
5. 对每项风险分别估计发生概率和代价，说明依据。区分已确认、待验证和已排除的破损方式。用真实 `file:line` 定位代码证据。

## 证据等级

1. 口头或静态直觉推测。无实证价值，不得据此判定「安全」。
2. 核对变更所涉及的精确源码，以及锁定版本的第三方库源码（含本地 patch）。仅看签名或文档达不到本级。
3. 沿真实调用链逐步排查时序与边界条件，排除具体失败路径，附 `file:line`。
4. 编写并运行隔离复现脚本，或直接实跑锁定依赖或目标模块的真实代码，验证关键安全事实。
5. 在真实运行中的应用或目标环境端到端跑通，观测实际结果并验证关键安全事实。单独跑隔离库或局部单测达不到本级。

尽力推进到第 4 或 5 级。只报证据实际达到的等级。无法实证的断言标「未证实」，第 1 级不得写「安全」。

## 固定输出

全文按 `unslop` 写作。用口语、短句、正常大小写。多用句号，少用逗号。用句号或逗号拆开插述，不用破折号或括号替代。禁用 U+2014 和 U+2013 作插语标记。一个概念始终用同一个名称。

1. 改动概述。点明行为变化及触及的边界。
2. 安全核心事实。给出实际证据等级、实证命令、退出码和输出。证据缺失时标「未证实」并说明卡点。
3. 风险清单。逐条给出破损方式、`file:line`、发生概率和代价、验证方法与实证。待验证项标「未证实」。
4. 已排除项。只列证据已排除的破损方式，附验证范围与结果。
5. 合并前建议检查。列出成本最低的复现或测试，附所写脚本和运行命令。
