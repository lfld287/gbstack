# 根治重复的 agent 错误

让 agent 即使只看打开的文件、照抄最近示例、走最短能编译的路径，也无法重犯同类错误。

## 1. 归类重复错误

检查近期 commit、revert、评审意见、agent 指令文件和 workaround 注释。同一根因至少出现 2 次才成类，记录各次证据和错误路径。

## 2. 选最高有效层根治

从 L1 到 L4 选能阻止该类错误的最高层。禁止只写文档或规则了事。

1. **L1 架构消除**。一份状态只归一个所有者，隐藏内部模块使错误 `import` 直接失败，统一数据源，删除旧路径和死代码。
2. **L2 类型／Lint／CI 门禁**。报错直接指出替代路径、符号或文件。存量违规多时，仅对新增违规判失败。
3. **L3 行为测试**。修正或删除行为已坏仍通过、仅改内部实现就失败的测试，锁定可观察行为。
4. **L4 文档／规则**。仅记录结构或检查无法替代、确需判断的情形。

## 3. 逐类修复并验真

按频次逐类修复。用真实历史错误证明新防线会拒绝错误路径，并验证正确路径通过。本地与 CI 用同一命令。例外须行内写明原因、过期日和人类批准记录。单机直接修复和复验。Swarm 由 Coordinator 分配各类改动并复验，成员禁止二次派发。

## 4. 维护对照表

在指令文档中维护「规则 ↔ 强制手段」对照表。已有规则缺强制手段且错误再次出现时，同次变更升到最高有效层。结构已杜绝的错误，直接删除对应规则和表项。

## 输出

逐类列出错误、重复证据、所选层级、为何更高层不适用和验真结果。
