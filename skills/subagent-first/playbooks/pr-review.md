# PR 讲解与审查

**定位**　面向 PR / diff，先讲清改了什么、如何工作（`how`）与为何如此设计（`why`），再独立审查潜在 bug、回归、影响面与可落地的改进点。

**硬门禁**　默认只读，免写前基线，跳过 `worker`。`reviewer` 和 `scout` 均不得写文件，包括临时文件、脚本和夹具。复现或验证确需写入时，本轮列出缺失证据，待用户授权后由 Coordinator 采集写前基线，再派 `worker`。必派独立 `reviewer`，走 Review Gate 默认双 Native（`gemini-4-neon-xhigh` + `claude-opus-5-5-high`）交叉审查。常规审查免 Codex 预检，重点交叉排查无运行时证据的过度防御性建议。仅在用户显式要求 Codex 审查或触发 `council` 时做 Codex 预检并引入 `reviewer-codex`。讲解与发现须附 `path:line` 或可核验的 PR/commit 证据，跳过纯风格 nit。

1. **锁定审查范围。** 派 `scout` 按用户指定的输入只读取证，按模块或关注点整理改动，必要时补查调用方与测试。
   - 分支或 commit 对比：读取 `GIT_OPTIONAL_LOCKS=0 git diff <base>...<head> --no-ext-diff --no-textconv` 的完整输出。
   - 本地未提交改动：分别读取暂存、未暂存 diff，并读取范围内相关未跟踪文件的内容。
   - 远程 PR：记录可核验的 base/head SHA，读取该版本的完整补丁，并查 PR 描述、关联讨论与 commit 列表。
   - 任一输入无法完整取得时，在 `未审完:` 列明缺失证据、受影响范围及原因。
2. **并行拆解 how / why 与独立审查。** 无依赖角色同轮并行。
   1. Coordinator 在 `scout` 的 brief 中引用 [`how`](../../how/SKILL.md) 与 [`why`](../../why/SKILL.md)，由 `scout` 直接追踪改动前后的调用链、状态／数据流与模块边界，并从 PR、commit 与历史记录查证设计动机和取舍。
   2. 按硬门禁派独立 `reviewer`，对照完整 diff 与周边上下文排查逻辑 bug、边界条件、回归风险、覆盖缺口及可落地的结构／设计改进点。常规双 Native 中任一方不可用或低配额，或用户显式锁定单一模型（含单路 Codex）时，保留获授权模式，在 `未审完:` 写明缺少异构交叉审查及原因，禁止静默放行或回退。
   3. 涉及公共接口、核心逻辑、安全、并发、迁移或高风险大 diff 时，另按 [`blast-radius`](../../blast-radius/SKILL.md) 排查 diff 外隐性破坏，并按 [`interrogate`](../../interrogate/SKILL.md) 由双 Native（`gemini-4-neon-xhigh` + `claude-opus-5-5-high`）执行异构对抗审查与只读复跑。复现或验证确需写入时按硬门禁处理。任一方不可用或用户锁定单一模型时，在 `未审完:` 写明缺少的异构审查覆盖及原因，禁止静默回退。
3. **合并讲解与审查交付。** 按 [`teach`](../../teach/SKILL.md) 将 `how` 与 `why` 组织为核心目标 → 动机与取舍 → 运行链路与关键改动。汇总前逐条判断**是否值得做**，剔除无运行时证据的过度防御与低收益改动，写明运行时证据、触发风险及修复收益与成本的取舍依据。审查结论分节给出 `阻塞:`（有实证且值得修的必改项）、`建议:`（有收益的可选改进，附根因与改法）、`覆盖缺口:`（缺失的测试覆盖）、`未确认:`（推论标「推断」并附依据，未记载的设计动机标「记录未说明」）。有未覆盖范围、证据不全或审查失败时，单列 `未审完:`，说明范围及原因。终稿经 [`unslop`](../../unslop/SKILL.md) 去水。
4. **收口与转场。** 发现阻塞 bug 或待落地改进时，报告结论，待用户拍板后再转入 `bug-fix`、`refactoring` 或 `feature`。
