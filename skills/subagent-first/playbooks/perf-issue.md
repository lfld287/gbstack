# 性能问题

**硬门禁**　用实测数据说明瓶颈及各次优化的效果。严禁用读源码代替测量，严禁未实测先声称性能天花板。

1. **建立基线。** 在真实运行表面采集指标及 profiling／trace 证据，改代码前用这些证据定位热点瓶颈，禁止仅凭总耗时猜测热点。核对样本数、冷态／热态、环境噪声及前后测量口径，记录复测条件。
2. **按成本排假设。** 追踪代码，按七级成本从低到高逐级试探，达到目标即停。
   1. 不做。
   2. 不重做（缓存／记忆化）。
   3. 少做。
   4. 晚做（懒加载／延迟计算）。
   5. 后台做（异步／移出关键路径）。
   6. 并发做。
   7. 降单次成本。
3. **逐项验证。** 跨边界先用 [`architect`](../../architect/SKILL.md) 定型。派 `worker` 逐项实现，每项单独采集 trace，验证各自效果。
4. **同表面对比。** 按基线条件复测，比较优化前后按同一口径采集的 profile／trace 和指标，给出实测数值、delta 与产物路径。
