# Bug 修复

**硬门禁**　每行交付代码都须追溯到运行时证据。无证据的「可能有用」防御兜底一律回滚，只交付证据支持的最小修复。

1. **亲自复现。** Coordinator 在真实运行界面复现，记录步骤、输入和原始失败输出。可派 `scout` 定向复现。只有尝尽可行路径仍无法触达时，才写明具体原因并请用户复现。
2. **二分定位根因。** 用 [`how`](../../how/SKILL.md) 追踪子系统，用 [`why`](../../why/SKILL.md) 查回归历史，列出候选机制。每轮选择能排除最多剩余候选的切分，用运行时证据淘汰假设，必要时插桩实测。确认唯一存活机制及系统首次出错点后才进修复。
3. **最小修复。** 跨边界先用 [`architect`](../../architect/SKILL.md) 定型。给 `worker` 明确 scope、根因证据和验收方式，禁止加入无证据兜底。
4. **同界面复验。** 重跑同一复现步骤，逐字贴出先失败、后通过的原始输出。单测只能证明分支行为，Bug 是否消失以真实界面的结果为准。
5. **编排提交。** 推荐先落失败复现测试，再叠修复提交。按 Review Gate 判定是否派独立 `reviewer`，验收后由 Coordinator 提交。

**反模式**　未复现先改代码、加「可能有用」的兜底、仅靠单测验收。
