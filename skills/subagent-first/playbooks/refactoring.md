# 重构

**硬门禁**　行为不变，只改结构。顺手发现的新需求或 Bug 单独处理，先按已钉定的契约交付结构重构。

1. **钉定行为契约。** 改动前建立 characterization test、snapshot 或 equivalence harness，捕捉现有行为。Typecheck 和 lint 不算契约。
2. **命名缺失的领域结构。** 新结构须消除分支或非法状态。只增加间接层的方案舍弃。跨边界先用 [`architect`](../../architect/SKILL.md) 定型。
3. **先减后加。** 先删死代码、单调用方 wrapper、冗余校验与孤儿引用。猜测性清理一律回滚。
4. **小步保绿。** 用 [`blast-radius`](../../blast-radius/SKILL.md) 查齐调用方，逐文件核对重命名。仅对所有调用方均在仓库内且可控的内部边界，同波次迁移全部调用方并删除旧 API，禁止遗留兼容垫片或新旧并行路径。涉及有外部调用方的公开入口时，保留对外兼容契约，或在引入破坏性变更前报告并请用户决定。
5. **证明真实产物等价。** 使用产物 diff 脚本、基线回放或真实界面冒烟，记录对照结果。
6. **核验认知负担。** 检查调用层数、隐式状态或分支是否减少。读者认知负担未下降就回滚。
7. **验收与提交。** 按减法、重塑、清理的顺序验收，由 Coordinator 编排提交。
