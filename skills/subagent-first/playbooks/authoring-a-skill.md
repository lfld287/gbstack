# 技能编写

**定位**　编写或修订任意仓库或插件中的 `SKILL.md`。

**硬门禁**　疑则删。只保留改变决策的指令，先理顺结构，用直接命令写清要做什么，只解释易混淆之处。按路径委托其他技能，省去复述。发现尚未沉淀的高频工作流时，提议新建 skill。

1. **写清触发与决策。** 明确何时用、何时跳过、哪些条件改变下一步，再编写 `SKILL.md`。易变的字段、命令或配置清单直接链接到定义它们的类型、配置文件或 README，避免在技能正文中硬编码。触发条件或验收标准含混时，用 [`sharpen`](../../sharpen/SKILL.md) 收紧措辞。
2. **校验格式与路径。** 解析 YAML frontmatter，确认含 `name` 与 `description`。逐一解析引用文件路径，检查跨 skill 链接可达。
3. **验证规则。** 为结构性规则补验证用例，覆盖触发边界和影响结果的分支。主观风格规则可跳过。
4. **收尾。** 按 Review Gate 决定是否派审，交付 skill 摘要、关键设计决策与校验说明。
