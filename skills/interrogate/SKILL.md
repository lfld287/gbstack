# 对抗审查

用独立视角挑战实现，只报告经验证的发现。严禁直接改代码修复。

## 1. 界定意图（Frame）

- 优先审查用户指定的目标。未指定时，以基准分支与 `HEAD` 的 merge-base 为起点，对照当前工作树，纳入范围内的暂存、未暂存和相关未跟踪内容。
- 用自己的一句话重述预期行为和边界。意图不明时先向用户确认，再开展审查。

## 2. 隔离对抗（Challenge）

- 让对抗者独立检查同一快照和意图。使用只读环境或隔离临时副本、worktree。隔离环境须拷入范围内的未提交变更。
- Swarm 的 `reviewer` 遵循 `agents/reviewer.md`，在任何目录（包括隔离副本和 worktree）都严格只读。禁止落盘脚本、测试夹具或临时产物，只执行无写入副作用的只读检查命令。确需落盘时，由具备写入授权且已核对有效基线的角色在隔离环境预先准备。
- Swarm 由顶层 Coordinator 按 `skills/subagent-first/SKILL.md` 的授权模型矩阵派发，异构交叉审查默认组合为 Codex `reviewer-codex` 与 Native `gemini-4-neon-xhigh`。仅在 Gemini 低配额时，才可按矩阵将 Native 成员原地切换到 `claude-opus-5-5-high`。禁止为凑异构跳过低配额条件直接选用 Claude。成员只完成自身审查并交回 Coordinator，禁止二次派发。
- 单机先判定当前代理是否已为被派发成员（如非 Swarm 的 `invoke_subagent` 子代理或 `run_workflow` 步骤）。已派发成员严禁再次调用 `invoke_subagent` 或二次派活，只在当前上下文内独立完成对抗验证并回报调用方。未被派发且已获调用授权时，可在隔离副本或 worktree 中用 `invoke_subagent` 独立挑战，例如分别检查边界输入、状态一致性和回归。无法独立调用时分视角检查，并如实说明来源。
- 每位对抗者须在自身权限内实际运行测试、复现脚本或检查命令举证。每项只交标题、精确命令、实际输出和意图期望。

## 3. 复跑验真（Verify）

- 在同一快照和等效环境中逐条复跑命令。只有实际输出确实显示失败且该失败破坏意图时才保留。
- 合并同根因项并保留全部来源。纳入所有对抗者去重后经筛选保留的已验证发现，禁止按来源或排名取舍。
- 剔除未实际运行的推测、复跑未证实或未破坏意图的项、纯风格／命名／结构抱怨、仅在假设性未来变更后才触发的风险、无运行时证据的过度防御性建议（多余空值检查、异常吞咽、假想分支、过度包装），以及修复收益低于引入成本的低价值改动。

## 输出

1. **意图重述**。一句话写出预期行为与边界。
2. **已验证发现**。每项含标题、精确命令、实际输出、如何破坏意图及发现来源。无则写「无已验证发现」。
3. **已剔除项**。按来源列出剔除条数及原因。
